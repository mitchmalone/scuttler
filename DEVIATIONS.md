# Deviations

Where this project diverges from the jig standard. Every entry has a justification and, where the divergence should eventually close, a trigger. Deviations are documented, never silent — an empty file means full compliance.

| Deviation                                                                                                                                                  | Why                                                                                                                                                                                                                                                                                                                                                                                                                                         | Reconverge when                                                                                                                   |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Signing, notarization, and the smoke tests run locally in `scripts/release.sh`, not in CI                                                                  | Developer ID identity and the notary keychain profile live in the local keychain — no secrets in env or CI. The smoke tests need a real Mac with the app installed (scripted since 2026-11-01, DECISIONS). The tag-triggered workflow owns everything after the GitHub Release.                                                                                                                                                             | Never (physics).                                                                                                                  |
| Older tooling majors at the root (pnpm 11, eslint 9, commitlint 19, TypeScript 5.8, lefthook 1, prettier-plugin-sort-imports 5) than the jig template pins | Reconciled repo, not a fresh stamp — major bumps are separate, verifiable upgrades, not part of a restructure. Dependabot raises them as PRs (TypeScript 6 is #19).                                                                                                                                                                                                                                                                         | Next scheduled dependency pass (the open Dependabot PRs).                                                                         |
| CI runs `verify` as two jobs — `verify:node` on Linux and `verify:shell` + `verify:rust` on macOS — not one `pnpm verify` step                             | The Rust half (Tauri, AppKit, objc2) and the zsh setup CLI's tests (which fake macOS `defaults`) only build and run on macOS; the Node half is faster and cheaper on Linux. Together the jobs run every script `pnpm verify` runs, so hooks and CI do not drift.                                                                                                                                                                            | Readiness item "make CI run `pnpm verify` once" (Backlog), or macOS runners become cheap enough to run the whole gate in one job. |
| `packages/setup` (the Machine rung's CLI) is zsh 5.9, not TypeScript                                                                                       | It must run with nothing but macOS present — before Node or Bun exist on a fresh Mac — and macOS ships zsh 5.9. Inherited from the distro repo's deviation (folded 2026-09-11).                                                                                                                                                                                                                                                             | The setup CLI outgrows shell, or the installer can bootstrap a runtime first.                                                     |
| Bun runs user code at runtime (widgets, plugin services, bundled scripts), not as a compiled-binary deliverable                                            | A plugin is a TypeScript file in a directory (DECISIONS 2026-08-19, 2026-08-27); Bun is the zero-config way to run one. The repo's own toolchain stays pnpm + Node; Bun is a runtime the app finds, never a build dependency.                                                                                                                                                                                                               | A Node-only runtime matches Bun's startup and single-file story.                                                                  |
| `interface` is used where the standard prefers `type` (kit props, bar/plugin contracts)                                                                    | Declaration merging for plugin-extensible shapes and readable error messages on the kit's prop types. Not enforced either way by lint.                                                                                                                                                                                                                                                                                                      | A lint rule, if the mix ever causes a bug.                                                                                        |
| The standard's web-product sections (two Vercel projects per product, Better Auth, Hono, Zod `src/env.ts`) are N/A                                         | There is no web product: one static site (`apps/www`, one Vercel project) and a desktop app with no server, no env tiers and no auth. Config is `config.json`; credentials are the user's own (invariant 2).                                                                                                                                                                                                                                | A server-side surface appears.                                                                                                    |
| **Infisical is N/A**: no `.infisical.json`, no `.envrc` / `.envrc.example`                                                                                 | The repo has no env-dependent code and no env tiers. Release credentials live in the macOS keychain (Developer ID identity, the `launcharr-notary` notarytool profile), read by `scripts/release.sh` at time of use and never exported to env or disk. CI-only credentials (`HOMEBREW_TAP_TOKEN`, `NOTION_API_KEY`, the mitchmalone.com deploy hook) are GitHub Actions secrets used only by the release fan-out; nothing local needs them. | An app or script needs a secret or env value outside the keychain or GitHub Actions secrets.                                      |
| Local dev ports are the framework defaults (panel Vite 1420/1421, site Next 3000), not a project-unique offset                                             | Tauri fixes the panel's port in `tauri.conf.json` (`devUrl`, `strictPort`); the site's port is only used for occasional copy work. Recorded in `AGENTS.md`.                                                                                                                                                                                                                                                                                 | Another project's stack routinely runs beside this one on the same Mac and collides.                                              |
