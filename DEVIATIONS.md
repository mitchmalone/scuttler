# Deviations

Where this project diverges from the jig standard. Every entry has a justification and, where the divergence should eventually close, a trigger. Deviations are documented, never silent — an empty file means full compliance.

| Deviation                                                                                                                             | Why                                                                                                                                                                                                                                                                             | Reconverge when                                                               |
| ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Rust/Tauri standards delta (no `unwrap`/`expect` outside tests, `thiserror` domain errors, `cargo clippy -- -D warnings` in `verify`) | The jig standard is TypeScript-first; the desktop app is half Rust. Delta follows the jig desktop-tauri flavor's `docs/RUST.md`.                                                                                                                                                | The jig absorbs a Rust standard section.                                      |
| Signing, notarization, and the smoke tests run locally in `scripts/release.sh`, not in CI                                             | Developer ID identity and the notary keychain profile live in the local keychain — no secrets in env or CI. The smoke tests need a real Mac with the app installed (scripted since 2026-11-01, DECISIONS). The tag-triggered workflow owns everything after the GitHub Release. | Never (physics).                                                              |
| Performance budgets are requirements, not aspirations — the table lives in `AGENTS.md` and release notes must carry measured numbers  | The product is a launcher; latency is the product.                                                                                                                                                                                                                              | n/a — the jig recommends this pattern for perf-sensitive projects.            |
| Older tooling majors at the root (eslint 9, commitlint 19, TypeScript 5.8) than the jig template pins                                 | Reconciled repo, not a fresh stamp — major bumps are separate, verifiable upgrades, not part of the restructure.                                                                                                                                                                | Next scheduled dependency pass.                                               |
| `packages/setup` (the Machine rung's CLI) is zsh 5.9, not TypeScript                                                                  | It must run with nothing but macOS present — before Node or Bun exist on a fresh Mac — and macOS ships zsh 5.9. Inherited from the distro repo's deviation (folded 2026-09-11).                                                                                                 | The setup CLI outgrows shell, or the installer can bootstrap a runtime first. |
| Bun runs user code at runtime (widgets, plugin services, bundled scripts), not as a compiled-binary deliverable                       | A plugin is a TypeScript file in a directory (DECISIONS 2026-08-19, 2026-08-27); Bun is the zero-config way to run one. The repo's own toolchain stays pnpm + Node; Bun is a runtime the app finds, never a build dependency.                                                   | A Node-only runtime matches Bun's startup and single-file story.              |
| `interface` is used where the standard prefers `type` (kit props, bar/plugin contracts)                                               | Declaration merging for plugin-extensible shapes and readable error messages on the kit's prop types. Not enforced either way by lint.                                                                                                                                          | A lint rule, if the mix ever causes a bug.                                    |
| The standard's web-product sections (two Vercel projects per product, Better Auth, Hono, Zod `src/env.ts`, Infisical tiers) are N/A   | There is no web product: one static site (`apps/www`, one Vercel project) and a desktop app with no server, no env tiers and no auth. Config is `config.json`; credentials are the user's own (invariant 2).                                                                    | A server-side surface appears.                                                |
