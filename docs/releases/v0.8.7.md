## Breaking changes

- none in config, state or paths. **One thing to redo by hand if you ran
  `scuttler sudoers on` under v0.8.6:** open Settings → Machine and press "allow admin"
  (the system admin dialog, your Mac password, once). The rule v0.8.6 wrote names
  Homebrew's own `mas`, a file your user owns, and that is the security fix below; the
  updates panel's App Store row reads "needs admin once" until the rule is rewritten.
  If you never ran it, nothing changes for you.
- A cloned (installed) theme no longer contributes its own `ghostty`, `tmux.conf`,
  `p10k-colors.zsh`, `delta.gitconfig` or `neovim.lua`; those are rendered from its
  palette. Built-in and hand-made themes are unaffected.

## Highlights

**Security: the admin rule no longer hands out root.** v0.8.6's `scuttler sudoers on`
wrote a NOPASSWD rule naming `/opt/homebrew/bin/mas`. sudo checks the path, not who owns
the file, and that file belongs to you, so anything running as you could replace it and
be root with no password and no sheet. The rule now names
`/usr/local/libexec/scuttler/mas`, a root-owned copy made when the rule is installed,
and the panel runs that copy. When Homebrew upgrades mas the row says the copy differs
and asks for admin once more. If you installed the rule under v0.8.6, rewrite it
(Settings → Machine → "allow admin"), or remove it with "remove" there or
`scuttler sudoers off` (DECISIONS 2026-11-08).

**Security: a theme is data.** An installed theme's palette values reached p10k, git and
Neovim config unescaped, so a theme repo could run code. Every palette value is now
validated before any template sees it (colours are `#rrggbb`, names are plain), and a
cloned theme ships only data files. Also: rustls, webpki-roots and Next.js bumped past
their open advisories; both audits are clean.

**The admin rule installs from a click.** No terminal, no bundle path: press `↵` on the
App Store row in the updates panel, or "allow admin" in Settings → Machine, and the
system's own admin dialog asks for your Mac password once. The step that runs as root is
a fixed script inside the app, run with an empty environment and absolute paths; nothing
you own executes as root. `scuttler sudoers on | off | status` still work from a
terminal and write the same rule. Each upgrade is still approved by the Touch ID sheet,
and the app itself still only ever runs `sudo -n`.

**The bar steps aside for fullscreen apps.** While the app in front covers a whole
display (a game in borderless fullscreen, a native-fullscreen video), the bar on that
display hides, and returns when you switch away. It reads window frames only, which
needs no permission. Settings → Menubar → Layout → "Hide the bar over fullscreen apps",
on by default; off asks the window server nothing.

**Fixes.** A fresh profile on a light-mode Mac stays on the `scuttler` theme instead of
being switched to `solarized-light`. pnpm upgrades in the updates panel reach `latest`
(a 0.x caret in the global manifest used to pin the row at the old version while
reporting success).

**Not yet run by a person.** Two paths in this release passed every automated check
but had not had their hands-on run when it was cut: the admin dialog end to end
(install, remove, cancel) and the bar against a real fullscreen game. If either
misbehaves, the fallbacks are `scuttler sudoers on` in a terminal and the Settings
toggle above.

## Performance receipts

| Metric                         | Budget   | This release                                       |
| ------------------------------ | -------- | -------------------------------------------------- |
| Hotkey → panel visible         | < 100 ms | 0.32 ms at v0.8.0; path untouched, not re-measured |
| Cold start → hotkey registered | < 1 s    | 194 ms                                             |
| Idle memory (the receipt)      | < 120 MB | 113.5 MB                                           |

Receipt: `scripts/mem.sh --receipt` on this build (`e401f5f`, release profile, `tauri
build --bundles app`), the primary Mac (Mac17,6, 128 GB, one display, macOS 27.2.1), run
under a fresh profile, which is the reference config (bar on, agents monitor off, no
plugin services, Desktop rung off), 2026-11-13. Three launches, each read from a minute
after launch: 127.0, 113.5 and 112.8 MB, median 113.5 MB (v0.8.6 read 114.4 MB); cold
start 697, 194 and 190 ms from the same launches, median 194 ms. The first launch was
taken about fifteen minutes after a reboot with the build just finished (load average 16) and is the outlier in both numbers; the two after it agree. The script's
agents-monitor warning reads this Mac's own config, not the fresh profile's. Nothing in
this release is resident: the fullscreen check is one window-list read after an app or
Space change and on the existing 5 s heartbeat, the admin dialog holds an Authorization
reference for one answer. The summon path has no change; the hotkey → panel number is
v0.8.0's.
