## Breaking changes

- none. Config, state, the bundle id and every path are as in v0.8.5. One thing to
  redo by hand, once, if you want App Store updates in the panel: `scuttler sudoers on`
  (one admin password; the CLI lives at
  `/Applications/scuttler.app/Contents/Resources/setup/bin/scuttler` until `scuttler link`
  has run). The rule it writes now also names `mas`; until then the App Store row says
  "needs setup once" and nothing else changes.

## Highlights

**Upgrade everything upgrades everything, the App Store included.** `mas` 7 needs root
to update an app, and from the panel there was no one to give it: on a Mac whose sudo
starts with Touch ID, the runner sat twenty minutes on a prompt that was never shown,
holding every job behind it. Now the App Store is a root source. Press `a` (or `↵` on an
App Store row) and the system's own approval sheet comes up at once: Touch ID, Apple
Watch, or your password. Homebrew, pnpm and mise start meanwhile; the App Store job joins
the queue the moment you approve, running under the sudoers rule you installed with
`scuttler sudoers on`. Decline, and the panel says "App Store skipped · not approved" and
everything else still runs. Without the rule the row says what to run once and `c` copies
it. The app still never asks for a password itself and only ever runs `sudo -n`: the
sheet is LocalAuthentication, the root is the same rule that lets `awake` switch sleep
off, four commands wider (DECISIONS 2026-11-06).

**The runner cannot hang any more.** Every upgrade the panel runs finds a `sudo -n`
first on its PATH, so a cask that reaches for root fails in a second with "a password is
required" in its tail instead of waiting forever; each child runs in its own process
group; cancel is TERM, then KILL for anything that ignored it; and a job silent for
fifteen minutes is killed with a line saying so.

**An agent cell says what the pane shows.** The bar's agent cells no longer trust a
sequence of Claude Code hook events to know whether an agent is working, waiting on you,
or done. Every two seconds, for each cell that reads working or needs you, and on every
hook event, scuttler reads the live bottom of the pane itself (`tmux capture-pane`) and
classifies it against a rule file for that agent: a spinner line is working, a question
form or a permission prompt is needs you, a bare prompt box is done. A transcript viewer
or model picker left open changes nothing. The hook now only identifies and labels a
session; it cannot flip its state. This ends the run of hook-sequence bugs: the away
recap that re-marked finished cells "working" for a day, the idle notification that
promoted every finished cell to "needs you", the question that read as "working". There
are 22 rule files in `apps/desktop/src-tauri/agents/` (Claude Code, Codex, Copilot,
Cursor, Gemini, Cline, Kiro, OpenCode, Amp, Devin and more), one TOML file each in the
shape [herdr](https://herdr.dev) uses, derived from its public catalogue under Apache-2.0
and credited in `THIRD-PARTY-LICENSES.md`. A pane running any of them is a cell with no
hook installed at all; a wrong cell is a screen capture and one new line in that agent's
file. The agents panel row names the rule that fired ("seen: …"). No new process: one
`capture-pane` per active pane per tick.

**A quicklink answers to its name.** `youtube gcn` searches YouTube; so does `yt gcn`.
A quicklink fires by its shortcode and by its name when the name is one word, case
forgiven, because people forget shortcodes and the two are one and the same.
Fuzzy-matching a quicklink (`youtu`) and pressing Enter opens the site root, not the raw
template with `{query}` in it, which is what 0.8.5 did. And Tab now completes: `you` ⇥
fills the prompt with `youtube `, `lor` ⇥ with `lorem `. Tab never leaves the prompt.
The help panel lists both words for each quicklink.

## Performance receipts

| Metric                         | Budget   | This release                                       |
| ------------------------------ | -------- | -------------------------------------------------- |
| Hotkey → panel visible         | < 100 ms | 0.32 ms at v0.8.0; path untouched, not re-measured |
| Cold start → hotkey registered | < 1 s    | 198 ms                                             |
| Idle memory (the receipt)      | < 120 MB | 114.4 MB                                           |

Receipt: `scripts/mem.sh --receipt` on this build (`50a3671`, release profile, `tauri
build --bundles app`), the primary Mac (Mac17,6, 128 GB, one display, macOS 27.2), run
under a fresh profile, which is the reference config (bar on, agents monitor off, no
plugin services, Desktop rung off), 2026-11-06: three readings 10 s apart from a minute
after launch, 130.5 / 114.4 / 114.4 MB, median 114.4 MB (v0.8.5 read 113.5 MB). Cold
start is the same launch's own report. The script's two warnings read this Mac's own
config, not the fresh profile's, and the two child processes at the sampling instant are
the bar's once-a-second `aerospace` call under a fresh profile, as at v0.8.5. Nothing in
this release is resident: the approval sheet is a LocalAuthentication context that lives
for one answer, the sudo shim is a file, the stall watchdog is a thread that exists only
while an upgrade runs, the agent rule tables are a few KB of text read at start. The
summon path has no change; the hotkey → panel number is v0.8.0's.
